1Problem and significance

A graph-structured constrained optimization problem is a triple of a graph, a constraint set, and an objective. Decision variables live on the nodes and edges of the graph, and the constraints determine which assignments are feasible:

\[P=(G,\,C,\,f),\qquad X(C)=\{\,x\in\Omega \;:\; c(x)=\text{true}\ \ \forall c\in C\,\},\qquad x^\star\in\arg\min_{x\in X(C)} f(x).\]

Here \(G=(V,E)\) is the problem graph (buses and lines, cities and roads), \(\Omega\) the space of complete assignments, and \(C\) a set of equality, inequality, and domain predicates, including integrality.

In deployed systems such as power grids, logistics, and scheduling, \(G\) and \(f\) are comparatively stable, while \(C\) changes with operating conditions, regulation, and reliability criteria. Two consequences follow.

  • Feasible sets are built from a small number of recurring constraint families: conservation and capacity in physical networks, and degree, flow, capacity, and time-window constraints in combinatorial problems. The constraint set, not the instance, is therefore the shared structure across tasks.
  • Learned solvers fix \(C\) at training time. A solver \(F^{(T)}_\theta\) trained for task \(T\) absorbs its constraints into its weights, so adding or tightening a single constraint requires a new model or a task adapter.

The goal is a single solver whose input includes the constraint specification itself, so that changing \(C\) changes the input, not the parameters:

\[\hat{x}=F_\theta(G,\,C),\qquad \hat{x}\in X(C),\qquad f(\hat{x})\approx f(x^\star)\quad\text{for constraint sets } C \text{ not seen in training.}\]

2Research questions

Equation (2) raises three requirements: constraints must be represented in a way that respects their algebraic structure, the representation must not depend on how a constraint is written, and it must be composed with the instance so that new combinations generalize. Each requirement becomes a research question, answered by a component of the method and tested by a specific experiment.

3Method

CONSTRAINER has three components: a constraint encoder that maps each \(c\in C\) to an embedding \(z_c\in\mathbb{R}^d\); a heterogeneous graph transformer over \(G\) that reads those embeddings through cross-attention; and a task decoder. Algorithm 1 gives the forward pass; the subsections define each step.

Algorithm 1  CONSTRAINER forward pass

Input: problem graph \(G=(V,E)\); constraint set \(C\); typed instance features on \(V\).  Output: solution \(\hat{x}\).

  1. for each \(c\in C\): parse \(c\) into an operator DAG \(A_c\);  \(z_c\leftarrow \mathrm{POOL}\big(\mathrm{MPNN}_L(A_c)\big)\)  ▷ Eqs. (3)–(5); cached across instances
  2. \(Z_C\leftarrow\{z_c\}_{c\in C}\)
  3. for each \(i\in V\): \(h_i^{(0)}\leftarrow\sum_{\tau\ \text{on}\ i}\big[\phi_{\mathrm{var}}(\tau)\oplus\phi(\mathrm{value}(\tau))\big]\)  ▷ Eq. (7)
  4. for \(\ell=0,\dots,L/2-1\): \(h^{(\ell+1)}\leftarrow \mathrm{GT}^{(\ell)}(h^{(\ell)};G)\)  ▷ structural reasoning
  5. for each \(i\in V\): \(h_i^{(L/2)}\leftarrow h_i^{(L/2)}+\sum_{c\in C}\alpha_{ic}W_v z_c\)  ▷ Eq. (8), constraint conditioning
  6. for \(\ell=L/2,\dots,L-1\): \(h^{(\ell+1)}\leftarrow \mathrm{GT}^{(\ell)}(h^{(\ell)};G)\)  ▷ propagate constraint context
  7. \(\hat{x}\leftarrow D_\theta(\{h_i^{(L)}\}_{i\in V})\)  ▷ Eq. (9): parallel readout or masked autoregressive decoding

3.1Constraints as operator graphs

Each constraint is written as the computation graph of its expression, a directed acyclic graph \(A_c=(V_c,E_c)\). Leaves are decision variables and numerical constants; internal nodes are operators (\(+\), \(\times\), \(\mathrm{pow}\), \(\le\), \(=\), \(\ge\)); edges carry argument roles. The line-flow limit \(P^2+Q^2\le S_{\max}^2\), for example, is a tree rooted at \(\le\) (Figure 1b). Node states are initialized by type and refined by \(L\) rounds of typed message passing:

\[h_v^{(0)}=\begin{cases}\phi_{\mathrm{var}}(v) & v \text{ a variable}\\ \phi_{\mathrm{const}}(v) & v \text{ a constant or bound}\\ \phi_{\mathrm{op}}(v) & v \text{ an operator}\end{cases}\qquad h_v^{(\ell+1)}=\psi^{(\ell)}\Big(h_v^{(\ell)},\ \textstyle\sum_{u:(u,v)\in E_c}\phi^{(\ell)}\big(h_u^{(\ell)},e_{uv}\big)\Big)\]

A permutation-invariant attention pooling over the final node states gives the constraint embedding

\[z_c=\mathrm{POOL}\big\{h_v^{(L)} : v\in V_c\big\}\equiv\phi_\theta(c)\in\mathbb{R}^d.\]

The representable class is exactly the set of constraints that reduce to a finite DAG over the operator vocabulary: linear, quadratic, polynomial, and algebraic nonlinear constraints, and structural properties with compact algebraic reformulations (flow- and cut-based encodings). A new operator is added by extending the lookup table \(\phi_{\mathrm{op}}\); the backbone, cross-attention, and decoder are unchanged.

3.2Contrastive invariance (RQ1)

The embedding should depend on the feasible region a constraint defines, not on its surface syntax. The encoder is trained with an InfoNCE objective in which positives \(c^+=T(c)\) are admissible DAG-level rewrites and negatives \(\{c^-_k\}_{k=1}^K\) are structurally similar but change feasibility:

\[\mathcal{L}_{\mathrm{con}}(c)=-\log\frac{\exp\big(\mathrm{sim}(z_c,z_{c^+})/\tau\big)}{\exp\big(\mathrm{sim}(z_c,z_{c^+})/\tau\big)+\sum_{k=1}^{K}\exp\big(\mathrm{sim}(z_c,z_{c^-_k})/\tau\big)},\]

with \(\mathrm{sim}\) the cosine similarity and \(\tau\) a temperature. Pairs are constructed per constraint type from the geometry of the set it defines (Table 2).

3.3Typed feature tokens

Instance data (power, capacity, demand, distance) enter as typed tokens that share the variable-type table \(\phi_{\mathrm{var}}\) with the constraint encoder, so the symbol \(P\) has the same type embedding in an instance feature and in a constraint. For a token \(\tau\) with type and scalar value,

\[h_\tau=\phi_{\mathrm{var}}(\tau)\oplus\phi\big(\mathrm{value}(\tau)\big),\]
\[h_i^{(0)}=\textstyle\sum_{\tau \text{ applies to } i} h_\tau ,\]

where \(\oplus\) is element-wise addition and the sum is permutation-invariant over the token set of node \(i\).

3.4Constraint-conditioned backbone (RQ2, RQ3)

The backbone is a heterogeneous graph transformer with \(L\) layers. Layers \(0,\dots,L/2-1\) reason over \(G\) alone. At depth \(L/2\), each variable queries the constraint set \(Z_C=\{z_c\}_{c\in C}\in\mathbb{R}^{|C|\times d}\):

\[\tilde{h}_i=\sum_{c\in C}\alpha_{ic}\,W_v z_c,\qquad \alpha_{ic}=\operatorname*{softmax}_{c\in C}\big\langle W_q h_i^{(L/2)},\,W_k z_c\big\rangle,\qquad h_i^{(L/2)}\leftarrow h_i^{(L/2)}+\tilde{h}_i.\]

Layers \(L/2,\dots,L-1\) then propagate the constraint-conditioned states across structurally related variables. Constraints enter only through the keys and values of Eq. (8), so adding, removing, or replacing a constraint changes the attention set and leaves the parameters unchanged. The cost of conditioning is the \(|V|\times|C|\) score matrix, linear in graph size for a fixed constraint set; constraint embeddings are computed once and cached at inference.

3.5Task decoder and training

The decoder maps \(H=\{h_i\}_{i\in V}\) to a solution. Continuous problems use a shared MLP applied to every variable in parallel; discrete problems use a masked autoregressive decoder that excludes constraint-violating actions at every step, so outputs on the MILP tasks are feasible by construction:

\[\hat{x}=D_\theta(H),\qquad \hat{x}_i=g_\theta(h_i)\ \ (i\in V)\ \text{ for continuous variables}.\]

The backbone and decoder are trained with supervised losses against solver-optimal solutions \(x^\star\), augmented with penalties on constraint violation; the encoder is trained with Eq. (5). Grid tasks train for 300 epochs and MILP tasks for 450, on NVIDIA H100 GPUs.

4Theoretical guarantees (RQ1)

For constraint \(c\), let \(A_{c,r}\in\{0,1\}^{n_c\times n_c}\) be the adjacency matrix of edges of type \(r\in\{1,\dots,R\}\) in its operator DAG, and define the reparameterization budget of a rewrite \(c'\) as

\[\delta=\max_{r\in\{1,\dots,R\}}\big\lVert A_{c,r}-A_{c',r}\big\rVert_2 .\]

Assumption. The encoder is a linear instantiation of Eq. (3): \(h_v^{(0)}=W_{\mathrm{init}}x_v\), messages \(m^{(\ell)}_{u\to v}=W^{(\ell)}_{r_{uv}}h^{(\ell)}_u\), and updates \(h^{(\ell+1)}_v=A^{(\ell)}h^{(\ell)}_v+B^{(\ell)}\sum_{u:(u,v)\in E_c}m^{(\ell)}_{u\to v}\), with \(\lVert A^{(\ell)}\rVert_2\le a\), \(\lVert B^{(\ell)}\rVert_2\le b\), \(\lVert W^{(\ell)}_r\rVert_2\le w\), and \(\lVert A_{c,r}\rVert_2\le\Delta\).

Theorem 1 (stability under reparameterization)

Under the assumption above, for any pair \((c,c')\) with budget \(\delta\), and with \(S=\mathbf{1}_n^\top\otimes I_d\) the sum-pooling operator,

\[\lVert z_c-z_{c'}\rVert_2\;\le\;\lVert S\rVert_2\,\big\lVert \mathrm{vec}(H^{(0)})\big\rVert_2\,\big(a+bwR\Delta\big)^{L}\cdot\frac{L\,bwR\,\delta}{a+bwR\Delta}.\]

The bound is linear in \(\delta\). The factor \((a+bwR\Delta)^L\) is the per-layer gain raised to the depth: near one, the encoder is close to non-expansive, and larger gains amplify perturbations with depth. Eq. (5) directly contracts embeddings of admissible rewrites and tightens the bound in practice.

Theorem 2 (transfer across constraint families)

Assume every test constraint is an admissible rewrite of some training constraint, and let \(F_\theta\) be \(L_F\)-Lipschitz in its stacked constraint embeddings. Replace each test constraint by its nearest training neighbor in embedding space, giving \(Z_{C^{\mathrm{nn}}}\). If training achieves \(\mathcal{L}_{\mathrm{con}}\le\varepsilon\) with \(K\) negatives and every negative satisfies \(\mathrm{sim}(z_c,z_{c^-_k})\le\rho<1\), then

\[\big\lVert F_\theta(G,f,Z_{C^{\mathrm{test}}})-F_\theta(G,f,Z_{C^{\mathrm{nn}}})\big\rVert\;\le\;L_F\sqrt{|C^{\mathrm{test}}|}\,\sqrt{2\big(1-\rho-\tau(\log K-\log(e^{\varepsilon}-1))\big)}.\]

The prediction shift grows linearly in the predictor's sensitivity \(L_F\) and only as \(\sqrt{|C^{\mathrm{test}}|}\) in the number of test constraints. A lower contrastive loss \(\varepsilon\) or more negatives \(K\) tighten it.

Text embeddings recover only part of the benefit of structured encoding, so the operator graph carries compositional information that surface semantics lose. Injection at \(L/2\) is best: earlier injection precedes enough structural context, and later injection leaves too few layers to propagate it.

7Future directions

Three extensions follow from the results. The operator vocabulary can be extended to logical and global combinatorial constraints that currently enter only through algebraic reformulations. Feasibility repair, now a post-hoc step (Table 9), can be moved into the decoder as a differentiable projection onto \(X(C)\). Finally, the gap growth on 2000-bus grids (Table 8) motivates hierarchical or sparse constraint attention for large networks.
