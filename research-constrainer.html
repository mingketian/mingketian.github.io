CONSTRAINER: Promptable Graph-Structured Optimization via Constraint Conditioning

Zeeshan Memon, Mingke Tian, Xinyuan Song, Hongwei Jin, Kibaek Kim, Liang Zhao

Paper (PDF) ↗Full-size figure ↗Cite

Learned solvers for graph-structured optimization usually bake their constraints into training, so a new constraint means a new model. CONSTRAINER treats constraints as a prompt: they are written down symbolically, encoded on their own, and injected into a graph transformer when the problem is solved. One model can then follow the constraint set it is given, including on a problem family it was not trained on.

1Problem setup

We consider optimization problems defined on a graph, where the instance fixes the structure and a separate list of constraints restricts which solutions are allowed:

\[\min_{\mathbf{x}}\ f_G(\mathbf{x})\qquad \text{subject to}\qquad c_j(\mathbf{x})\le 0,\quad j=1,\dots,m\]

where

\(G=(V,E)\)
the problem graph, for example a power network or a routing graph
\(\mathbf{x}\)
decision variables attached to nodes and edges
\(f_G\)
the objective of the instance
\(c_j\)
the \(j\)-th constraint, given as a symbolic expression such as a line limit \(P^2+Q^2\le S_{\max}^2\)

The goal is a single model that reads both \(G\) and the constraint list \(\{c_j\}\), instead of one model per constraint set.

2Encoding constraints as operator graphs

Each constraint is parsed into a directed acyclic graph of operators and encoded by a graph neural network:

\[c_j\;\longmapsto\;\mathrm{DAG}(c_j),\qquad \mathbf{e}_j=\mathrm{GNN}\big(\mathrm{DAG}(c_j)\big)\in\mathbb{R}^d\]

where

\(\mathrm{DAG}(c_j)\)
the operator graph of \(c_j\): leaves are variables and constants, internal nodes are operators such as \(+\), \(\mathrm{pow}\), and \(\le\)
\(\mathbf{e}_j\)
the constraint embedding used as a prompt
\(d\)
the embedding width

The encoder is trained contrastively: algebraically equivalent rewrites of a constraint are pulled together, and edits that change which solutions are feasible are pushed apart. The embedding therefore reflects what a constraint allows, not how it happens to be written.

3Conditioning the graph transformer

The problem graph is processed by heterogeneous graph transformer (HGT) layers. Between them, a cross-attention block lets every node read the constraint prompt:

\[\alpha_{vj}=\operatorname*{softmax}_{j}\!\left(\frac{(\mathbf{W}_Q\mathbf{h}_v)^{\top}(\mathbf{W}_K\mathbf{e}_j)}{\sqrt{d}}\right),\qquad \tilde{\mathbf{h}}_v=\sum_{j=1}^{m}\alpha_{vj}\,\mathbf{W}_V\mathbf{e}_j\]

where

\(\mathbf{h}_v\)
the state of node \(v\) after the preceding HGT layers
\(\mathbf{W}_Q,\mathbf{W}_K,\mathbf{W}_V\)
learned query, key, and value projections
\(\alpha_{vj}\)
how much node \(v\) attends to constraint \(j\)
\(\tilde{\mathbf{h}}_v\)
the constraint information passed to the remaining HGT layers and the task decoder

Because constraints enter only through this attention, adding, removing, or replacing a constraint changes the prompt rather than the network.

4Results

  • 45%lower optimality gap on ATSP than GOAL (0.91% → 0.50%)
  • 99.02%feasibility on DC optimal power flow
  • Zero-shottransfer to DC optimal power flow on IEEE power-grid benchmarks

5Conclusion

Separating what the problem is (the graph) from what is allowed (the constraints) turns a learned solver into a promptable one. Constraint conditioning improves solution quality on routing and carries over, without retraining, to power-flow problems with physical constraints.
