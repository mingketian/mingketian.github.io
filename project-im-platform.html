On this pageProblemArchitectureResults

1Problem

An instant-messaging backend holds a long-lived connection per client, so its connection tier is stateful while its business logic is not. The system must scale both tiers horizontally, deliver messages in order and without loss under burst traffic, recover sessions when a node fails, and ship new releases without dropping connections.

2Architecture

Table 1. Components and their roles.
LayerTechnologyRole
Connection tierNetty, WebSocketHorizontally scalable cluster holding client connections
ServicesJava Spring CloudStateless microservices for messaging and social features
DiscoveryZooKeeperTracks the stateful Netty nodes and routes users to them
MessagingRabbitMQFan-out routing, tuned for low intra-cluster latency
SessionsRedisDistributed session state and failover recovery
StorageMinIO, relational DBMultimedia objects and relational data
DeploymentContainersRolling upgrades and horizontal scaling

Messages enter through the connection tier and are published asynchronously; RabbitMQ fan-out delivers them to the services and back to the nodes holding each recipient. Asynchronous pipelines absorb bursts while preserving order, and Redis-held sessions let a client reconnect to any node after a failure. Containerized rolling upgrades replace nodes one at a time, so releases need no downtime.
